# ADR-0004: Editor-tunable style values in a data prefab

- **Status:** Accepted
- **Date:** 2026-10-31
- **Deciders:** tech-lead

## Context
ADR-0003 builds all UI from code, with tuning numbers in `assets/scripts/data/`. Some visual values (the word-length badge size, offset and colour on pinned letters) are easier to tune with sliders and a colour picker than by editing constants and reloading. Cocos Creator 2.4 has no ScriptableObject-style data asset, but a prefab whose root node carries a data-only component behaves like one.

## Decision
`assets/resources/prefabs/PieceStyle.prefab` is a template prefab: its root carries `assets/scripts/view/PieceStyle.js`, a component with references to three child Label nodes (`letter`, `badge`, `counter`) plus one colour (`letterColorOnTint`). Designers open the prefab in Creator and edit the labels directly: font size, colour, position, alignment, cache mode, all visible in the Scene view. The labels are authored at the reference cell size `LAYOUT.MAX_CELL` (180 px); `PieceNode` clones a template per use with `cc.instantiate` and scales font size and position by `cellSize / MAX_CELL`, then sets the text and shows or hides it (badge only on pinned letters, counter only while frozen). The Unity analogy is a prefab whose child objects are copied into every instance, rather than a ScriptableObject of numbers.

`Game` instantiates the prefab once after the textures and keeps the instance off-stage. If the prefab is missing or a template is unassigned, `PieceStyle.createDefault()` builds the same tree from `Layout`/`Palette`, so the game runs without it and the constants stay the engine-free truth for tests.

The prefab JSON is generated by hand when its structure changes (Creator's own serialized form; the script uuid in its `.meta` is stable). Value tuning happens in the editor only.

An earlier version held numbers (sizes as cell fractions, colours, offsets) on the component with an edit-mode preview component drawing sample cells. It was dropped: the labels themselves in the prefab are the preview, and a Label's own inspector already offers everything the numbers did.

## Consequences
- What the Scene view shows at the prefab is exactly what a full-size cell renders; smaller cells scale down proportionally.
- Adding a text element is one new child node plus one `cc.Node` property on `PieceStyle`; `PieceNode` clones it.
- The clone scales font size and position, not `node.scale`, so the piece animations that tween scale (lift, counter tick) keep their meaning.
- More template prefabs (HUD, popup) can follow the same pattern, one prefab per concern.

## Alternatives considered
- Inspector properties on `Game` in `Main.fire`: would put tuning data in the scene, which is editor-owned and never hand-edited.
- A custom `cc.Asset` subclass: needs an editor extension with its own importer in 2.4; too heavy for a few numbers.
- JSON under `resources/`: already used for levels, but gives text editing, not sliders or a colour picker.
