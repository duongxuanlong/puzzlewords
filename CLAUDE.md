# Puzzle Words — project constitution

Grid-based word puzzle for mobile. **Cocos Creator 2.4.15, JavaScript (CommonJS), portrait 1080x1920.**
First milestone is the Athena Studio programmer test; the codebase is structured to grow into a live game.
The user is a Unity developer new to Cocos: explain Cocos concepts with Unity analogies when relevant.

## Layout
- `assets/` — the only folder Creator scans. Every file in it gets a `.meta`. Never put tooling here.
  - `scenes/Main.fire` — single scene (Canvas + Camera). UI is built from code.
- `preview-templates/` — project override of Creator's browser-preview page; its "Fit window" device sizes the game to the window so the preview never scrolls.
  - `scripts/model/` — **engine-free** game logic (Board, Piece, WordMatcher, FreezeSystem, LevelSchema). No `cc` allowed (eslint enforces).
  - `scripts/data/` — engine-free constants, palettes, level index.
  - `scripts/systems/` — engine-free services (save/progression, event bus).
  - `scripts/view/` — cc.Class components rendering the board and pieces, drag handling.
  - `scripts/ui/` — cc.Class components for HUD, popups, screen flow.
  - `resources/levels/level_NNN.json` — level data, loaded with `cc.resources.load`.
  - `resources/textures/{common,challenge1,challenge2}/` — art from the provided pack, under `resources/` so code can load it (`cc.resources.loadDir('textures')`).
- `tests/` — Node `node:test` suites for the model (`npm test`).
- `tools/` — validator, build script, Claude hooks. `docs/` — ADRs, specs, backlog.
- `library/ temp/ local/ build/` — generated by Creator, gitignored, never edited.

## Hard rules
1. Model, data and systems never import or reference `cc`. They are tested in plain Node.
2. Only `view/` and `ui/` touch the engine. One component per concern.
3. Script filenames are unique project-wide and modules are required by bare name (`require('Board')`), which is how Creator resolves modules. Tests get the same via NODE_PATH in `npm test`.
4. Never hand-edit `.meta` files, generated folders, or `.fire` scenes (a hook blocks this). Scenes change in the editor.
5. Level data is validated by `LevelSchema`; `npm run validate:levels` must pass.
6. **The user commits manually.** Never run `git commit`, `git push` or create tags. Leave changes in the working tree and draft a commit message in chat if useful.
7. Design decisions go in `docs/adr/`. Spec interpretations live in `docs/specs/word-puzzle-core.md` and feed the README.

## Commands
- `npm test` — model unit tests. `npm run lint` — eslint. `npm run validate:levels` — level data.
- `npm run check` — all three; also the git pre-commit gate (`git config core.hooksPath .githooks`).
- `npm run solver:report -- [level_001 ...] [--metric=moves|slides] [--weight=N] [--max-states=N] [--analyze]` — solver timing and results. Use this (pre-approved) instead of writing ad-hoc probe scripts; extend `tools/solver-report.js` if it lacks an option.
- `node tools/solve-level.js assets/resources/levels/level_00*.json` — difficulty metrics and walkthrough per level (pre-approved).
- Run these commands plainly so the allowlist matches and the user is not prompted: no `time`, `${...}` / `$PIPESTATUS`, heredocs, `cd … &&` or scratch `node` scripts around them. The Bash tool already reports the exit code; a trailing `| tail -N` is fine.
- `npm run build:web` — headless Creator build to `build/web-mobile` (set `COCOS_CREATOR` if the editor is elsewhere). `npm run serve:web` serves it at http://localhost:8080.
- Editor: `/Applications/Cocos/Creator/2.4.15/CocosCreator.app` → open this folder → Play for browser preview.

## Gameplay rules as implemented (see docs/specs/word-puzzle-core.md)
- Pieces slide one cell at a time through free cells following the finger; they never overlap and cannot pass through other pieces. Multi-cell blocks move as one unit. Every step is committed to the board immediately.
- A word clears when a chain of 4-adjacent cells (any direction per step, no reuse, no other word's pin) starting at its pinned letter spells it. The longest valid prefix chain is tinted in the word colour after every drop. Frozen cells do not count until thawed.
- Frozen pieces show a counter and hide their letters; every cleared word decrements all counters; at zero the ice is removed and the piece becomes a normal piece.
- Pinned letters never move and display their word's length and color.

## Cocos facts to rely on (verified against the installed engine)
- Components: `cc.Class({ extends: cc.Component, properties: {...}, onLoad(){}, start(){}, update(dt){} })`.
- Touch: `node.on(cc.Node.EventType.TOUCH_START|TOUCH_MOVE|TOUCH_END|TOUCH_CANCEL, handler, this)`; `event.getLocation()` is world space; `node.convertToNodeSpaceAR(worldPoint)`.
- Tweens: `cc.tween(node).to(0.2, { position: cc.v3(x, y) }, { easing: 'quadOut' }).call(fn).start()`.
- Ordering: `node.zIndex`; parent via `node.setParent`/`addChild`. Resources: `cc.resources.load(path, cc.JsonAsset, cb)`.
- Design resolution 1080x1920. `Game` sets the Canvas to fit width on portrait screens and to fit both axes (letterboxed phone column) on windows wider than 9:16 such as the desktop preview, so the full layout is always visible and never stretched. Use `cc.Widget` for HUD anchoring.
- Local API reference: `/Applications/Cocos/Creator/2.4.15/CocosCreator.app/Contents/Resources/engine/cocos2d/` (source) and `.../Resources/engine/api.d.ts`. Prefer these over web docs, which mostly cover 3.x.
